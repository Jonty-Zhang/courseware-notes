# 课件知识点与解题方法（纯方法版）

把一个或多个课件 PDF 整理成一份 Word：**知识点 + 解题方法卡，不含例题**。方法卡要能独立指导做题，读者看不到任何例题，也能知道看到什么题该用什么方法、怎么做、哪里容易错。知识点照样配课件截图。

姊妹 skill `review-f` 产出含例题版。两者共用 `scripts/` 和 `references/`。

## 为什么必须看页面图，不能只读文字层

PPT 导出的 PDF 文字层通常不可靠：公式里的 Σ、矢量箭头、上下标会变成私用区乱码（如 ``）或被拆成碎片，受力图、电路图、曲线全是图片。只读文字层写出来的公式和结论会出错。所以本流程把每页渲染成图片逐页看，文字层只用来快速定位。

## 工作流程

### 0. 确认范围

确认要处理哪些 PDF、输出到哪个文件夹（默认放在课件旁边）。所有课件合成一份 Word，每份课件对应一个一级标题。用户另有学校或老师的排版要求时，以其为准。

### 1. 渲染课件

```bash
python3 scripts/render_pages.py "课件.pdf" --out work/ch1
```

输出 `pages/`（逐页 PNG）、`sheets/`（每张 4 页的拼图，带页码标签）、`text/`（文字层，仅作索引）和 `manifest.json`。依赖 poppler（`pdftoppm`/`pdftotext`）和 Pillow。

### 2. 逐页阅读，整理清单

按顺序读完每一张拼图，每读完一章就把清单写进 `work/inventory.md`，防止上下文过长被压缩后丢失。格式见 `references/inventory-format.md`：跳过页、知识点 K、方法 M、例题 E，每条带页码，能用图说明的知识点标上"图 pNN"。

例题虽然不进成品，也要读、要记：课件里的方法往往只在例题里体现（先取哪个对象、对哪一点取矩、怎么判临界），这些做法要提炼进方法卡。

覆盖要求：每一页要么被某条 K/M/E 引用，要么列在跳过页里。公式或小字看不清时，单独读 `pages/pNNN.png` 放大确认，不要猜。

### 3. 从例题里提炼方法

把每道例题归到某个方法 M 下，问三个问题：题目的什么特征让人选这个方法（识别信号）？关键的一步是什么（选对象、选矩心、取临界）？哪里容易做错？答案写进对应方法卡。课件里多道例题反复出现的技巧，单独成一张方法卡。

### 4. 截配图

能用图说明的地方就放图，比文字更直观：概念示意、受力图、几何关系、分类对比（力的平移、各类约束的约束力画法、摩擦角……），放在对应知识点段落后面，每章一般 3～9 张。例题的题图不放。几张小图需要对照看时，用 `compose_figures.py` 拼成一张带标签的对比图。照片、动画截图、装饰图不放。

```bash
python3 scripts/crop_figure.py "课件.pdf" crops.txt --out work/figs
python3 scripts/compose_figures.py work/figs/约束对比.jpg --cols 3 a.jpg:光滑面 b.jpg:圆柱铰链 …
```

裁剪清单每行 `名字 页码 x0 y0 x1 y1`，坐标是页面宽高的比例，从拼图或单页图上读。脚本按 220 dpi 重新渲染裁剪，默认存 JPEG，并生成 `_review.png`；看一遍审查图，把带进标题文字、边框线或截掉标注的框调好再裁。

### 5. 写 Markdown 源稿

每章一个文件，结构见 `references/output-template.md`，写法约定见 `references/markdown-conventions.md`。每章是"（一）知识点 +（二）解题方法"，不写 `::: example` 块。方法卡格式：

```markdown
### 2. 截面法

**识别信号：** 只求桁架中个别杆件的内力，特别是中部的杆。

**做法：** （1）由整体求出需要的支座反力；（2）作截面截断所求杆，一般不超过 3 根未知杆；（3）取受力较简单的一侧；（4）==矩心选在另外两根未知杆的交点上==，一个方程求出所求杆力；另两杆平行时改用垂直于它们的投影方程。

**关键点：** 截面可以是曲线；先判零杆，常能把截不开的截面变成可解的。〔5-p15～21〕
```

纯方法版的方法卡比含例题版写得更细：

- **识别信号**写题目里看得见的特征，让读者看到题就能对上方法。
- **做法**写成可执行的（1）（2）（3）步骤，关键的选择要说明理由（"对 B 取矩，因为另外两个未知力都过 B"）。
- **关键点**写易错处和检查办法；需要时用一句话点出课件里的典型情形（"如多跨梁先算附属部分"），但不展开计算。

最后加一章"题型与方法总表"，按题型汇总识别信号、首选做法和关键点。

其余要求：每个知识点和方法标课件页码 `〔章-p页〕`；重点用 `==…==` 标成浅蓝色，全文 3%～8%，不超过 20%；源稿里不写文档标题和过程性文字。

### 6. 构建 Word

```bash
python3 scripts/build_docx.py ch1.md ch2.md … 总表.md \
    -o "课程名_知识点与解题方法（纯方法版）.docx" \
    --toc --title "课程名 知识点与解题方法" --subtitle "（纯方法版）" --drop-examples
```

`--drop-examples` 保证即使源稿里残留了例题块也会被删掉。首页是居中标题（宋体二号加粗）和版本副标题（楷体小三），下面接自动目录；用户明确不要标题时去掉 `--title`。正文按 word-format 规范排版：A4、2.5 cm 页边距、宋体五号、1.5 倍行距、宋体小三/黑体小四标题、楷体图表题、原生表格、可编辑公式、页码，每章另起一页。

### 7. 检查

```bash
python3 scripts/check_docx.py out.docx --source ch1.md … --drop-examples
```

检查 A4、页边距、标题与正文字体字号、表格单元格段距为 0、公式数与源稿一致（没有残留 `$`）、每张图都有图题、浅蓝重点占比、过程性文字。另外通读一遍方法卡，确认没有"如例所示""见上例"这类指向例题的话。全部通过才交付。机器装有 LibreOffice 时，可再 `soffice --headless --convert-to pdf` 后逐页看图；没有渲染器时，在交付说明里请用户用 Word/WPS 打开确认，并允许更新域，让目录页码刷新。

### 8. 交付

docx 放到课件文件夹。回复里说明：覆盖了哪些课件，知识点、方法卡、配图各有多少，发现的课件错误及处理，以及没能验证的地方。

## 文件

- `scripts/render_pages.py`：渲染页面、拼图、文字层。
- `scripts/crop_figure.py`：按比例框批量裁剪配图并生成审查图。
- `scripts/compose_figures.py`：把几张小图拼成一张带标签的对比图。
- `scripts/build_docx.py`：Markdown → 排版好的 docx。
- `scripts/check_docx.py`：不依赖渲染器的结构检查。
- `references/output-template.md`：章节结构、方法卡模板。
- `references/markdown-conventions.md`：源稿 Markdown 写法。
- `references/inventory-format.md`：逐页清单格式。
