# 输出结构与写法模板

## 全文结构

```text
文档标题 + 版本副标题（--title / --subtitle）
目录（自动）
一、<第 1 份课件的主题>
  （一）知识点
    1. …   2. …
  （二）解题方法
    1. <方法名>   ← 方法卡，后面跟 0～2 个例题块
    2. …
二、<第 2 份课件的主题>
…
N、<课程>题型与方法总表   ← 一张表
```

- 一份课件对应一个一级标题；一份课件内容很多、明显分成几块时，可以拆成两个一级标题。
- 一级标题由构建脚本设置为另起一页。
- 文档标题由构建参数生成，源稿里不写。

## 知识点写法

每个三级标题下写一到三段完整的话，包括：

- 定义或定理的准确表述，条件要写全（"充分必要""仅适用于刚体"之类的限定不能丢）；
- 核心公式，单独成行；
- 容易混淆的概念放在一起对比（如"分力与投影""固定铰与固定端"）；
- 段末页码 `〔章-p页〕`。

知识点之间结构相似、适合对比时（约束类型、各类力系的平衡方程数），用表格。

能用图说明的知识点紧跟一张课件配图，放在对应段落后面：

```markdown
（3）二力平衡公理：……〔1-p11〕

![二力构件的受力沿两受力点连线](k1_p11.jpg){width=45%}
```

图题写成一句说明图意的话（"不平行三力平衡必汇交于一点"），不要只写名词（"三力平衡"）。分类对比用拼图，宽度 85%～95%。

## 方法卡写法

```markdown
### 2. 截面法

**适用情形：** 只求个别杆件内力，特别是桁架中部的杆。

**做法：** （1）……；（2）……；（3）……；（4）==矩心选在另外两根未知杆的交点上==，……

**关键点：** ……〔5-p15～21〕
```

- 标签用 **适用情形 / 识别信号**、**做法**、**关键点** 三个，需要时加 **易错**。
- "识别信号"写题目里能看到的特征（"问保持平衡时力的范围""杆件两端铰接、中间不受力"），让读者看到题就能对上方法。
- "做法"写成可执行的步骤，用（1）（2）（3）编号，不用 Markdown 列表。
- 纯方法版没有例题，方法卡本身要讲清楚"为什么这样选"，必要时用一句话举课件里的典型情形，但不展开计算。

## 例题块写法

```markdown
::: example
#### 例 4-2 雨蓬支撑杆（三矩式）〔4-p26〕

题目：已知……，求……。（照课件改写成完整的题目叙述）

![雨蓬结构](c4_p26.png){width=48%}

分析一句：为什么这样选研究对象/矩心。

$$\sum M_A=0:\ \sqrt2F_1-5F=0\ \Rightarrow\ F_1=\frac{5F}{\sqrt2}$$

……

**要点：** 一句话点出这道题体现的方法。

**注：** 课件中写作……，按……计算为……（仅在发现课件错误时写）
:::
```

- 例题编号按"章-序号"，标题写出题目特征和所用方法。
- 解题过程写到"列出哪个方程、得到什么结果"，课件里有的中间结果照写；课件省略的部分不要编具体数值。
- 配图宽度：结构简图 40%～55%，细长图 20%～30%，图题由脚本自动编号。

## 总表写法

四列：题型 | 识别信号 | 首选做法 | 关键点。每章 2～4 行，按章节顺序排列，每格一句短语。
